# 組織雙元能力（Organizational Ambidexterity）

## 命名與定位

Ambidextrous 字面意義「**左右手皆靈**」— 隱喻組織同時做兩件性質衝突的事。Grant Ch08 把 ambidexterity 與 [[concepts/dynamic-capabilities]] 並列為對付 [[concepts/organizational-inertia]] 的核心機制。^[inferred]

## 核心張力：Exploit vs Explore

| | Exploitation | Exploration |
|---|---|---|
| **時間軸** | 今天 | 明天 |
| **對象** | 既有業務、既有能力 | 新業務、新能力 |
| **邏輯** | 效率、改善、深耕 | 試誤、學習、突破 |
| **風險** | 低 | 高 |
| **指標** | 短期 KPI / ROI | 長期 option value |

組織單純 exploit → 短期賺錢但長期被顛覆；單純 explore → 燒錢沒成果。**Ambidexterity = 能同時做、而不是輪流做。**^[inferred]

## 兩型 ambidexterity

### Structural ambidexterity（O'Reilly & Tushman 主張）

**分離的組織單位**做 exploit vs explore：^[inferred]

- 主體事業專注 exploit（既有 BU / 既有 routines）
- 獨立創新單位專注 explore（R&D lab / 新事業部 / corporate venturing 單位）
- 高層 CEO 統籌兩邊資源分配與整合時機

典型結構：母公司 + 隔離的「skunkworks」/「new ventures」單位。

→ 詳見 [[entities/intel-NBI]]、[[synthesis/corporate-venturing-isolation-paradox]]（內部創投隔離悖論的案例）

### Contextual ambidexterity（Gibson & Birkinshaw 主張）

**同一群員工**根據情境**自己切換** exploit / explore 模式 — 不依賴結構分離，依賴：^[inferred]

- 文化（鼓勵實驗 + 紀律並存）
- 系統（時間配比、25% rule 之類）
- 個人能力（cognitive flexibility）

典型例：Google 經典「20% time」、3M 鼓勵內部實驗時間。

## Grant Ch08 案例：Hyundai 的 Product Sequencing

Grant 用 **Hyundai Motor 1968–1995** 作為「能力建構同時做 exploit + explore」的案例：^[extracted from Grant Ch08]

- SKD/CKD（exploit 既有組裝能力） → Pony（explore 自有車型） → Excel（exploit Pony 學到的東西） → Alpha engine（explore 新引擎能力） → Accent/Sonata（雙線並進）
- 每階段：**用既有能力產出 + 培養下一階段所需新能力**

→ 這是 sequencing ambidexterity：**時間軸上的交替**而非結構上的並列。^[inferred]

## 與 dynamic capabilities 的關係

| | Dynamic Capabilities | Organizational Ambidexterity |
|---|---|---|
| 焦點 | **能力本身**如何更新 | **組織結構**如何兼顧 exploit / explore |
| 提出者 | Teece | O'Reilly & Tushman / Gibson & Birkinshaw |
| 操作層 | 抽象（routine of routines）| 具體（組織設計 / 時間配比） |
| Grant 定位 | Ch08 Managing Strategic Change 章節 | 同章節，並列工具 |

兩者**互補不替代**：dynamic capabilities 提供「為什麼／要做什麼」；ambidexterity 提供「怎麼組織」。^[inferred]

## 限制／適用邊界

- Structural 模式風險：**隔離過頭，新單位產出無法整合回主業**（Intel NBI 案例的核心病灶）— 見 [[synthesis/corporate-venturing-isolation-paradox]]
- Contextual 模式風險：**員工被同時要求兩種模式，認知過載**；只有少數高 cognitive flexibility 員工能真做到 ^[inferred]
- Grant **未深入比較**兩型何時較佳；本頁的對照表為 Jason 整理 ^[inferred]
