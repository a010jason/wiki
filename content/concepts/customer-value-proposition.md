# Customer Value Proposition (CVP)

## What It Is

**CVP = Total Customer Benefit − Total Customer Cost** 的差額（跨不同 choices 比較）。^[extracted Ch07 p.4-7]

Kotler 16e 把 CVP 拆成 **三個 value domains** + **兩端 benefits/costs 結構**。

## 三個 Value Domains（Ch07 p.4）

CVP 不是單一維度，是三個並行領域的捆綁感知：

1. **Functional value**（功能價值） — 產品 / 服務的實用屬性能解決什麼問題
2. **Psychological value**（心理價值） — 形象、認同、情緒、地位
3. **Monetary value**（貨幣價值） — 直接價格與相關貨幣 outcomes

任何 offering 都同時跨這三個領域，只是比重不同。教師批註「FB → meta」案例：改名是想重塑 psychological value（從 social network 變成 metaverse pioneer）。^[inferred from instructor annotation]

## Benefits 端 — Total Customer Benefit（Ch07 p.5）

顧客感知到的 **四類 benefit**：

- **Product benefit** — 商品本身的價值
- **Services benefit** — 配套服務（安裝、維修、訓練）
- **Personnel benefit** — 接觸到的員工帶來的價值
- **Image benefit** — 品牌 / 公司形象帶來的價值

四類 benefit 各自橫跨 functional / psychological / monetary 三領域，是 4 × 3 矩陣。

## Costs 端 — Total Customer Cost（Ch07 p.6）

顧客在 **四段過程** 承受的成本：

- **Evaluating**（評估期）— 找資料、比較
- **Obtaining**（取得期）— 採購、運送
- **Using**（使用期）— 學習、運轉、維護
- **Disposing**（處置期）— 回收、報廢、棄置

每段橫跨 functional / psychological / monetary cost。**注意 "disposing" 一詞** — 含處置階段，呼應永續議題與循環經濟。

## Customer Value Analysis（CVA）四步驟（Ch07 p.9）

把 CVP 變成可操作分析：^[extracted Ch07 p.8-9]

1. Identify 顧客重視的 attributes / benefits
2. Assess 這些 attributes/benefits 的相對重要性
3. Assess 公司與 competitor 在 key attributes 上的 performance
4. **Monitor customer value over time** — 講義紅字「Dynamic!!!」強調這不是 one-shot

## 從 CVP 到 OVP — 3V Market Value Principle（Ch02）

Kotler Ch02 把 value 視角從「客戶 only」擴到三方：^[extracted Ch02 p.19-21 Figure 2.3]

- **Customer value** — 對客戶創造的價值
- **Collaborator value** — 對合作夥伴創造的價值（通路、供應商、agency）
- **Company value** — 對自家公司創造的價值

**三圓的交集 = Optimal Value Proposition (OVP)**。

意涵：好的 value proposition 不能只顧客戶（會餓死自己 + 通路），也不能只顧公司（會被客戶拋棄）— 必須三方都拿到 value。OVP 是 marketing strategy 的內核產出。

## 與 Osterwalder Value Proposition Canvas 的關係

Kotler 16e 在 CVP slide 引用 Strategyzer 的兩本書：^[extracted Ch07 p.7]

- 《Business Model Generation》(Osterwalder & Pigneur, Wiley)
- 《Value Proposition Design》(Strategyzer Series, Wiley)

對照：

| 框架 | 結構 | 強項 |
|---|---|---|
| Kotler CVP | Benefit − Cost (3 domains × 4 stages) | 完整、學術 |
| Osterwalder VPC | Customer Profile (Jobs/Pains/Gains) vs Value Map (Products/Pain Relievers/Gain Creators) | 視覺、可協作 |
| Kotler 3V → OVP | Customer + Collaborator + Company 交集 | 含通路與公司利益 |

三者不衝突 — Osterwalder VPC 適合 workshop 工具，Kotler CVP 適合分析框架，3V → OVP 適合 business model 對齊。

## Source 反例 / 質疑

- CVP 公式假設 **可加總 benefit / cost** — 但 psychological 與 monetary 在不同 unit，加總是 metaphor 不是算術。^[inferred — 隱含批評]
- CVA 第 4 步 "Monitor over time" 預設 value 是動態的，但 Kotler 沒給出「多久 monitor 一次」的指引。^[ambiguous]
- 3V → OVP 沒有 priority 機制：三方衝突時誰先誰後沒答案。^[ambiguous]

## Jason 觀察：醫療 AI 的 CVP

EBM PACS / AI 產品的 CVP 三領域：^[inferred — Jason 個人延伸]

- **Functional**：診斷準確度、turnaround time、誤判率
- **Psychological**：醫師對 AI 的信任、是否覺得「被工具搶工作」的負面 valence、向同行展示先進科技的 status value
- **Monetary**：模型 license 費用、整合 PACS 的工程費、健保給付狀況

四階段 cost 中，**disposing cost** 在醫療 AI 特別不被重視 — 舊模型如何 retire、舊資料如何遷移、醫院從 EBM 換到競品的 migration cost 沒有方法論。這是 EBM 可以做 customer-side competitive moat 的破口。
