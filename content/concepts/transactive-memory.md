# Transactive Memory System

專業知識在成員間**分散**，形成「誰知道什麼」的記憶系統。^[extracted]

不需每人都懂同樣的事，需懂：
1. **何時自己的專業相關**
2. **如何結合他人專業**

## Mental Model 與 TMS 的差異

- **Mental Model**：成員對團隊及任務重要面向的**共同理解**（everyone knows same thing）
- **Transactive Memory**：成員對「誰擁有哪部分專業」的**分散映射**（everyone knows who knows what）

兩者互補：TMS 讓 team scale 超越個人腦容量；Mental Model 讓 coordination 不必每次重溝通。

## 案例

- **Lacrosse Thompsons 三兄弟**（University at Albany）：默契極深，「不用言語就能溝通」— TMS + 高 mental model 的真實案例。^[extracted]
- **Mayo Clinic 動態 team**：每位新病人組成新團隊，靠每人對其他人專業的快速 map 完成 onboarding。^[inferred from Ch12]

## 脆弱性（source 自承）

TMS **系統脆弱** — 任一成員回應慢 / 遺忘 / 離開都讓 memory 系統失效。^[extracted]

→ 連結 [[concepts/team-interdependence]]：reciprocal / comprehensive 互賴的 team 對 TMS 的 dependence 最高，turnover 最痛。

## Mitigation / 工具

- **MWH（IT company）** 用 social network survey + software 繪製 informal network map，發現 well-connected experts；Asia region key manager 離職時，CEO 用 map 找 closest contacts 減損。^[extracted]
- **IBM、Solvay** 用 social network analysis 作為 management tool 找 fault lines、leadership transition / "baton passing"。^[extracted]

→ Network mapping 本質是把 TMS 從個人腦中 externalize 到工具中。

## Network Mapping 的副作用

source 自承：^[extracted]
- Leaders feel threatened
- 員工發現自己提名的人沒回提名 → 自尊受損
- "more connections aren't necessarily better" — niche expert 在 periphery 是 OK
- 過度連結者反而是 bottleneck
- Confidentiality 問題（map 共享過廣具破壞性）

**解方**：用 generic job titles 編碼、上層另出 most-connected list、個人可看自己那片但主管禁看。

## 反例 / 質疑

- TMS 預設「成員願意共享」— 高政治環境下 [[concepts/organizational-justice|injustice]] 反向激勵 hoarding。^[inferred]
- AI tools（如 Slack AI、Notion AI）正在取代部分 TMS — 把「誰知道什麼」externalize 成 retrievable index。對團隊 cohesion 與 trust 的影響 source 未討論。^[inferred]
