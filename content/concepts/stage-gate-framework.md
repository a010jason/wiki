# Stage-Gate Framework

## What It Is

Kotler 16e Ch18 Figure 18.1 — 新產品開發的 stage-gate 流程：^[extracted Ch18 Figure 18.1 p.7]

```
Idea         Concept       Business         Offering       Commercial
Generation → Development → Model Design → Implementation → Deployment
   ▼            ▼             ▼              ▼              ▼
Idea         Concept       Business        (Alpha+Beta)   Selective →
Validation   Validation    Validation                      Market
                                                          Expansion
                          [GATE]                          [GATE]
```

每個 stage 後接一個 gate（檢查點），不通過 → kill 專案。

源頭：**Robert G. Cooper, 1980s** 在加拿大顧問經驗下提出 stage-gate methodology，後成為 NPD 業界標準。Kotler 16e 沿用其框架。^[inferred — 業界共識]

## 5 個 Stage + 4 個 Validation Gate

### Stage 1: Idea Generation

兩種方式：^[extracted Ch18 p.10]
- **Top-down**：市場機會驅動（identify gap → 想方案）
- **Bottom-up**：發明驅動（先有 invention → 找市場應用）

工具：Lead user method、Crowdsourcing、競爭情報、員工建議。

### Gate 1: Idea Validation

評估兩個維度：^[extracted Ch18 p.11]
- **Desirability**：市場想要嗎？
- **Viability**：公司做得到嗎？

**兩類錯誤**：^[extracted Ch18 p.11]
- Type I：**拒絕好構想**（false negative）
- Type II：**接受劣構想**（false positive）

研究工具：market research、focus group、prototype test。

教科書 Figure 18.2 列「**Forces Fighting New Ideas**」5 種組織抵抗：^[extracted Ch18 p.12]
- "We've tried it before"
- "This isn't the right time"
- "It's not the way we do things"
- "We've done all right without it"
- "Let's discuss it at our next meeting"

詳見 [[concepts/forces-fighting-new-ideas]]。

### Stage 2: Concept Development

把 idea 細化為**可溝通的 concept**。^[extracted Ch18 p.14]

包括：
- 詳細功能規格
- 初步市場測試
- Target segment 定義
- 預估技術可行性

### Gate 2: Concept Validation

兩個關鍵問題：^[extracted Ch18 p.16]
1. **能否建立功能原型（prototype）**？
2. **是否優於替代方案**？

工具：
- **Prototype**（工作模型）— 驗證原始構想 + 排除潛在問題
- **Alpha testing**（內部評估）— 公司內部試用
- **Beta testing**（外部評估）— 與真實客戶試用

### Stage 3: Business Model Design

三個組成部分：^[extracted Ch18 Figure 18.3 p.19]
1. **目標市場**（target market）
2. **價值主張**（value proposition）— 對應 [[concepts/customer-value-proposition]]
3. **產品屬性**（product attributes）

對應 [[concepts/G-STIC-framework]] 的 Strategy（目標市場 + 價值主張）+ Tactics（產品屬性）。

### Gate 3: Business Model Validation

三層驗證：^[extracted Ch18 p.20]
- **Desirability**：客戶要不要？
- **Feasibility**：公司能不能做？
- **Viability**：商業上可不可持續（利潤、現金流、市場規模）？

意涵：concept validation 偏技術，business model validation 偏商業。兩個 gate 分工明確。

### Stage 4: Offering Implementation

兩部分：^[extracted Ch18 p.21-22]
1. **核心資源開發**（生產設施、IT、供應鏈、人才）
2. **市場產品開發**（最終產品 + 包裝 + 廣告 creative）

組織可能欠缺生產設施、供應鏈、配銷管道、熟練員工或資本 — 這是常見的死亡點。^[extracted Ch18 p.22]

### Stage 5: Commercial Deployment

三個關鍵活動：^[extracted Ch18 p.23-25]

1. **Selective market deployment**（選擇性部署）— 先在小範圍 / 自然環境試（StubHub 案例 p.22）
2. **Market expansion**（擴張）— 三項：
   - 擴大生產設施
   - 向全體目標客戶推廣
   - 確保市場全面供應

## Managing Innovation 五種組織策略

支持 stage-gate 的組織形式：^[extracted Ch18]

| 形式 | 邏輯 |
|---|---|
| **指派責任**（Innovation responsibility） | 設專責 innovation officer |
| **新產品部門**（New-product department） | 獨立部門負責整個 NPD |
| **創新中心**（Innovation centers） | 跨部門的中央 hub |
| **創業團隊**（Venture teams） | 內部創業團隊有預算與自主權 |
| **跨職能團隊**（Cross-functional teams） | R&D + 行銷 + 製造 + 財務跨組 |

延伸：**Intrapreneur**（組織內企業家） — 內部創業者，是 stage-gate 的 driving force。^[extracted Ch18 + 參見 [[concepts/intrapreneurship-vs-venture-capital]]]

## Source 反例 / 質疑

- **Stage-gate vs Agile / Lean Startup 衝突**：Lean Startup 主張**少 gate、快 iterate**；stage-gate 的 gate 數量可能拖慢創新。^[inferred — 業界爭議]
- **5 stage 過度線性**：實務常迭代回到 earlier stage（concept 拒絕 → 回 idea generation）。^[inferred]
- **大公司偏好 stage-gate、startup 偏好 lean**：source 沒討論組織規模的適配。^[ambiguous]
- **Gate 評審委員的偏見**：committee 易過度謹慎、Type I error（拒絕好點子）多。^[inferred]

## Jason 觀察：醫療 AI NPD 的 stage-gate 變形

醫療 AI 的 stage-gate 多了**臨床驗證**與**法規**兩層 gate：^[inferred — Jason 個人延伸]

```
Idea Gen → Idea Validation
         → Concept Dev → Concept Validation
         → Algorithm Dev → Internal Performance (AUC, sensitivity)
         → External Validation (multi-site)  ←── 醫療新增 gate
         → IRB / Clinical Trial               ←── 醫療新增 gate
         → Business Model Validation
         → FDA / TFDA / CE Mark               ←── 醫療新增 gate（殺手 gate）
         → Reimbursement Approval             ←── 醫療新增 gate
         → Commercial Deployment
         → Post-market Surveillance           ←── 醫療新增持續監控
```

意涵：醫療 AI 的 NPD 時程 = 一般 SaaS 的 3-5 倍，因為法規 gate 殺死大多數專案。

PM 建議：早期就把 FDA submission readiness 納入 concept validation（[[concepts/intended-vs-emergent-strategy]] 中的 anticipative thinking），不要等到 stage 5 才驚覺要 510(k)。
