# Whetten 四大 Building Blocks

David Whetten (1989) *Academy of Management Review* 14(4):490-495 提出。^[extracted]

## 四大 Building Block

| Block | 對應問題 | 內容 | 評估角度 |
|---|---|---|---|
| **Constructs** | **What** | 哪些 concept 對解釋 phenomenon 重要 | 完整性、相關性 |
| **Propositions** | **How** | 這些 concept 之間如何相關 | 方向、形式、強度 |
| **Logic** | **Why** | 為什麼這些 concept 相關 | 內部一致、可信度 |
| **Boundary conditions / Assumptions** | **Who, When, Where** | 在什麼情境下成立 | range、limits、scope |

## 各 block 詳解 ^[extracted]

### 1. Constructs（What）

詳見 [[concepts/concept-vs-construct-vs-variable]]。

選 construct 時要問：
- 涵蓋完整嗎？（missing constructs 會降低 explanatory power）
- 相關嗎？（marginally relevant construct 降低 parsimony）
- 操作化可行嗎？

### 2. Propositions（How）

兩 construct 之間的關係。詳見 [[concepts/proposition-vs-hypothesis]]。

寫 proposition 時要明示：
- 方向（positive / negative / curvilinear）
- 形式（直接 / 中介 / 調節）
- 強度（強 / 中 / 弱）

### 3. Logic（Why）

Whetten 強調這是最重要的 block。**「Why」才是 theory 的核心**。

Logic 的常見來源：
- 既有 theory 的延伸
- 跨領域 analogy（如核爆 critical mass → network effect）
- 第一原理推導

Sutton & Staw (1995) [[concepts/theory-vs-not-theory]] 強調：缺 logic 就不是 theory，無論 construct + proposition 多漂亮。

### 4. Boundary Conditions / Assumptions（Who, When, Where）

特別重要：是 research design 中可能影響結果、但**未被操縱**的因子。

**經典 boundary 案例** ^[extracted]：

| 案例 | Boundary |
|---|---|
| Kanemoto & MacLeod (1991) 勞動契約 | 美國 senior worker 有 exit market，日本 mid-career worker 幾乎沒有市場 → theory of contracts 在兩國表現不同 |
| Everaert & Bruggeman (2002) NPD 研究 | 假設 NPD 環境有三衝突目標（design quality / cost / dev time），design quality 最優先 |
| Kohli & Grover (2008) IT value | Boundary 限縮在 firm level 或 firm network level，不含 economy / individual level |

**重要提醒**：經濟與政治理論基於不同 underlying assumption，**不直接可比較**；若研究目標是組織內權力結構，不該用經濟理論。

## 對審稿 / 寫作的應用 ^[inferred]

審稿時逐 block 檢查：
- Construct 有遺漏？
- Proposition 方向不明？
- Logic 為什麼這樣關聯？
- Boundary 在哪裡？跨文化 / 跨產業會破嗎？

PM 寫 PRD 時也應對 4 block：
- **What**: 哪些 concept 重要？（user need / engagement / monetization）
- **How**: 這 feature 如何影響 KPI？
- **Why**: 為什麼這 mechanism 會 work？（這段最容易薄弱）
- **Boundary**: 哪些用戶、哪些情境、哪些市場不適用？
