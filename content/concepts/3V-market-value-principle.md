# 3V Market Value Principle

## What It Is

**3V** = Kotler 16e Ch02 把 value 視角從「客戶 only」擴到三方並陳（Figure 2.3）：^[extracted Ch02 p.19-21]

1. **Customer value** — 對客戶創造的價值
2. **Collaborator value** — 對合作夥伴（通路、供應商、agency）創造的價值
3. **Company value** — 對自家公司創造的價值

**三圓的 Venn 交集 = Optimal Value Proposition (OVP)**。

## 為什麼是三方而非單方

傳統「客戶至上」的行銷觀只看 Customer value，但實務上：

- 只顧客戶 → 通路抽不到佣金、公司賺不到錢 → 系統崩潰
- 只顧公司 → 客戶感到被剝削 → 流失 + 負評
- 只顧通路 → 客戶與公司關係斷線 → 教師批註：「HTC vs Samsung — HTC 出貨給 Carrier 而非 end user」

3V 框架強迫思考者「找到三方共贏的提案」，這就是 OVP 的「Optimal」意涵。^[inferred]

## 三個 V 各自的具體內容

### Customer value

= [[concepts/customer-value-proposition]]（Total Customer Benefit − Total Customer Cost）

橫跨 functional / psychological / monetary 三個 value domains，benefit 端 4 類 × cost 端 4 階段（evaluating / obtaining / using / disposing）。

### Collaborator value

通路與夥伴拿到什麼：
- 通路利潤、市場進入、品牌借力
- 學會 / KOL：研究素材、共同發表、社群影響力
- 供應商：穩定訂單、共同創新、長期合約

### Company value

公司拿到什麼：
- 短期：營收、毛利
- 長期：品牌權益、客戶 LTV、市場 share、學習效應 ([[concepts/scale-scope-learning]])

## OVP — 交集區的限制

OVP 是三圓**交集**，意味著：

- 三方都拿到的「最大公共子集」往往不是任何單方的最佳解
- 隨時間變化 — 客戶需求變、通路結構變、公司能力變，OVP 也要重新計算
- 教師批註「FB → Meta」是 OVP 重設的例子：FB 想擴大 Company value（從 social 到 metaverse），但 customer value 與 collaborator value 是否同步動 — 待 wiki-challenge

## 與 [[concepts/customer-value-proposition]] 的關係

兩者**不是替代**：

- **CVP** = 單向（客戶端）的 value 結構
- **3V** = 三方（客戶 + 通路 + 公司）的 value 平衡
- **OVP** = 三方交集的具體 value proposition 輸出

操作順序：先做 CVP 分析（客戶要什麼）→ 把 Collaborator value 與 Company value 疊上 → 三圓交集處輸出 OVP。

## 在 G-STIC 中的位置

3V → OVP 是 [[concepts/G-STIC-framework]] Strategy 步驟的最終產出：

```
G-STIC: Goal → Strategy → Tactics → ...
              ↓
         Strategy = Target Market (5C) + Value Proposition (3V → OVP)
                                          ↓
                                       OVP 餵給 Tactics 的 7Ts 設計
```

## Source 反例 / 質疑

- 3V 沒有 priority 機制：三方衝突時誰先誰後沒答案。例：低價（高 customer value） vs 通路利潤（高 collaborator value） vs 公司毛利（高 company value） — 三方在價格議題上零和。^[ambiguous]
- OVP「最優」是 Pareto 意義還是 sum-max 意義？source 未提。^[ambiguous]
- 「Collaborator value 也要創造」這個立場在「直接通路」(direct-to-consumer) 商業模式下退化 — 沒有 Collaborator 要服務，3V 變回 2V？^[inferred — 隱含批評]

## Jason 觀察：3V 套用到醫療 AI

EBM PACS / AI 的 3V 分析：^[inferred — Jason 個人延伸]

- **Customer value**：放射科醫師（功能 + 心理）、醫院（功能 + 貨幣）、病人（功能間接）
- **Collaborator value**：PACS vendor（互補產品搭售）、雲端商（流量）、學會（KOL 認證）、健保署（給付數據）
- **Company value**：營收、模型訓練資料、品牌、未來授權機會

醫療 AI 的特殊性：**Collaborator 結構很複雜**（PACS vendor、健保、學會、KOL 四種角色都要伺候），這是為什麼很多醫療 AI 新創卡在 GTM — 不是模型不準，是 OVP 漏掉了 Collaborator value。
