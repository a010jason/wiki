# G-STIC Framework

## What It Is

**G-STIC** 是 Kotler 16e Ch02 提出的 actionable marketing plan 五步驟框架：^[extracted Ch02 p.26-27 Figure 2.7]

1. **G**oal — 見：設定 ultimate criterion for success
2. **S**trategy — 識：定義 value created in target market（含 STP）
3. **T**actics — 謀：設計 market offering 的具體 7Ts
4. **I**mplementation — 斷/行：規劃 logistics of creating the offering
5. **C**ontrol — 控：定義監控 goal progress 的 metrics

教師中文口訣對應：**見 → 識 → 謀 → 斷 → 行 → 控**（最後一步「控」對應 C）。^[inferred from instructor annotation]

## 五步驟細節

### G — Goal（見）

兩維度：^[extracted Ch02 p.28]

- **Goal Focus**：Monetary goals（財務）vs Strategic goals（策略，例：市占率、品牌權益）
- **Performance Benchmarks**：Quantitative benchmarks（量化基準）+ Temporal benchmarks（時間錨點）

兩個維度合起來定義「成功長什麼樣 + 在什麼時間點 + 用什麼指標」。

### S — Strategy（識）

兩元件：^[extracted Ch02 p.13-14, p.29-30]

- **Target Market**（用 [[concepts/5C-target-market-framework]] 分析）
- **Value Proposition**（用 [[concepts/3V-market-value-principle]] 推導出 OVP）

策略層回答兩問：**誰要買？為什麼買？**

### T — Tactics（謀）

用 [[concepts/7Ts-marketing-tactics]] 設計 market offering：^[extracted Ch02 p.22-24]

Product / Service / Brand / Price / Incentives / Communication / Distribution

三組功能：
- **Designing value**：Product / Service / Brand / Price / Incentives
- **Communicating value**：Communication
- **Delivering value**：Distribution

### I — Implementation（斷 / 行）

三子步驟：^[extracted Ch02 p.31]

- **Resource development**（資源建構）
- **Development of the offering**（產品 / 服務開發）
- **Commercial deployment**（市場投放）

### C — Control（控）

兩個動作：^[extracted Ch02 p.32]

- **Evaluate performance** — 用 benchmarks 追蹤進度
- **Monitor the environment** — 環境變化時 corrective actions

回到 Goal 步驟形成 loop。

## 為什麼是 G-STIC 不是 STP

STP 是 G-STIC 的子結構（在 S 步驟的「Target Market」部分）。但 G-STIC 比 STP 多出三件事：

1. **明確的 Goal** — STP 沒有目標設定步驟
2. **Implementation 落地** — STP 沒有處理「怎麼做出來」
3. **Control 閉環** — STP 沒有監控與修正

因此 G-STIC 是 **行銷管理**（managerial）級別，STP 是 **行銷策略**（strategic）級別。

## 與 OKR / SMART 的關係

G-STIC 的 Goal 步驟與 [[concepts/OKR]] / SMART 在 goal-setting 上重疊，但角度不同：

| 框架 | 範疇 | 強項 |
|---|---|---|
| [[concepts/OKR]] | 全組織目標管理 | 自下而上 + 透明 + 衝刺週期 |
| SMART | 個人 / 任務目標 | 易記、易檢核（但缺 Difficult） |
| G-STIC Goal | 行銷計畫專用 | 整合 monetary + strategic + temporal benchmarks |

詳見 [[synthesis/G-STIC-vs-OKR-SMART]]。

## Marketing Plan 結構

G-STIC 落地為 marketing plan 的格式：^[extracted Ch02 p.33-36 Figure 2.8]

- Executive Summary（電梯說明）
- Situation Overview（公司端 + 市場端）
- **G-STIC section**（核心，五步驟展開）
- Exhibits（細節 / 證據）

Marketing plan 不是靜態文件 — Kotler 強調 needs periodic update + [[skills/marketing-audit]] 檢視。^[extracted Ch02 p.37-39]

## Why It Matters (Jason 角度)

對醫療 AI PM 而言，G-STIC 提供一個「比 OKR 更具體、比 STP 更完整」的行銷規劃模板。EBM PACS / AI 產品的行銷計畫如果跳過 G（目標）直接做 T（戰術），就會落入「整天在做活動但不知道為何成功 / 失敗」的 control 失效狀態。^[inferred — Jason 個人延伸]

## Source 反例 / 質疑（wiki-challenge 候選）

- Kotler 把 G-STIC 包裝為 **universal** actionable framework，未指出何時不適用：非營利、危機 pivot、blue-ocean exploration（無 benchmark 可參考）。^[ambiguous]
- 教師批註 BCG / GE Grid 的局限：「靜態、Oversimplify and Subjective、邊界模糊」 — 雖然是針對 Ch02 引用的 portfolio matrix，但延伸質疑也適用 G-STIC：planning 框架在高度不確定環境下的 frame collapse 問題。^[inferred from instructor annotation]
