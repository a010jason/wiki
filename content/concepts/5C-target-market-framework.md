# 5C Framework

## What It Is

**5C** = Kotler 16e Ch02 提出的目標市場分析五要素（Figure 2.2）：^[extracted Ch02 p.15-18]

1. **Customers** — 公司打算服務需求的個人或組織
2. **Collaborators** — 與公司合作為目標客戶創造價值的對象（通路、供應商、agency）
3. **Competitors** — 服務同一客戶同一需求的對手
4. **Company** — 開發與管理 market offering 的自家公司
5. **Context** — 公司與 collaborators 運作的環境

結構：**Customers 居中**；Company / Collaborators / Competitors 圍繞；Context 為最外圈虛線環境。

教師批註：「context = 未可知的環境、機會、危機」。^[inferred from instructor annotation]

## 五要素細節

### 1. Customers（中心）

目標客戶是 5C 分析的起點 — Kotler 框架是 **outside-in**，先理解市場再決定 offering，不是 inside-out 從產品出發。

對 Customers 的分析會延伸到：
- [[concepts/buying-decision-process-consumer]] — 5 階段消費者購買流程
- [[concepts/business-buying-process]] — 8 階段企業購買流程
- [[concepts/buying-center]] — B2B 多角色決策結構
- [[concepts/customer-persona]] — 客戶輪廓視覺化

### 2. Collaborators

**容易被忽略的 C** — 但通路、供應商、agency 都會影響 value delivery。

Kotler 的 [[concepts/3V-market-value-principle]] 把 collaborator value 拉到與 customer / company 同層 — 強調好的 value proposition 要三方共贏（OVP）。

### 3. Competitors

不只是現有 industry 對手，還包括：
- 替代品（substitutes）
- 潛在 entrant
- 跨界 disruptor（[[concepts/strategic-collisions]]）

呼應 [[concepts/porters-five-forces]] 但 5C 的 Competitors 範疇更寬。

### 4. Company

自家公司的 resources、capabilities、limitations。延伸到：
- [[concepts/VRIO-framework]] — 評估資源是否能撐起 sustainable advantage
- [[concepts/core-competency]] — Kotler Ch06 的三條件版
- [[concepts/value-chain]] — Porter 的內部活動分析

### 5. Context（外圈環境）

包含六個子要素：^[extracted Ch02 p.18]

- Economic
- Technological
- Legal
- Political
- Sociocultural
- Physical（環境 / 永續）

呼應傳統 PESTLE 框架，但範疇略有差異。

## 5C vs PESTLE vs Porter Five Forces

三個架構同類但不同層：^[inferred 跨框架比較]

| 框架 | 範疇 | 強項 | 弱項 |
|---|---|---|---|
| **5C** | Target market 級 | 含 Collaborator + Company 內視；以 Customer 為核心 | Context 子要素粗略 |
| **PESTLE** | 宏觀環境 | 純外部 | 不含 Company 與 Competitor |
| **Porter Five Forces** | Industry 級 | 競爭結構深入 | 不含 Customer 與 Collaborator |

教師批註：「5C product-market 而非 industry」 — 暗示 5C 比 Porter Five Forces 更「行銷」（消費者中心），Porter 更「策略」（產業結構中心）。^[inferred from instructor annotation]

詳見 [[synthesis/5C-vs-PESTLE-vs-Porter-five-forces]]。

## 在 G-STIC 中的位置

5C 是 [[concepts/G-STIC-framework]] 的 Strategy 步驟的「Target Market 分析」工具：

```
G-STIC: Goal → Strategy → Tactics → Implementation → Control
              ↓
         Strategy = Target Market + Value Proposition
                    ↓                ↓
                   5C 分析        3V → OVP
```

5C 完成後輸出餵給 [[concepts/STP-framework]] 的 Segmentation → Targeting，最終再用 [[concepts/3V-market-value-principle]] 推 value proposition。

## Source 反例 / 質疑

- 5C 的 Customers / Company / Competitors 與 SWOT 重疊很多，但 5C 多了 Collaborators 與 Context — Kotler 沒解釋為什麼不直接擴展 SWOT。^[ambiguous]
- Context 六要素的 priority 沒有指引：什麼產業情境下哪個 Context 子要素最重要？^[ambiguous]
- 教師批註「context = 機會 / 危機」暗示 Context 既是 input 也是判斷，但 framework 本身沒區分。^[inferred]

## Jason 觀察：醫療 AI 的 5C

EBM PACS / AI 產品的 5C 分析：^[inferred — Jason 個人延伸]

- **Customers**：放射科醫師（user）、IT 主管（buyer）、院長（approver）、健保署（payer）— 真實 buying center
- **Collaborators**：PACS vendor（Sectra / GE / Philips）、雲端供應商、學會、教學醫院 KOL
- **Competitors**：跨 segment（國際大廠 / 新創 / 院內 IT 自建）
- **Company**：EBM 自己的能力與資源限制
- **Context**：FDA / TFDA 認證、健保給付政策、醫療法規、臨床工作流、AI 信任氛圍

對「未上市的新模型」做行銷規劃時，5C 比單純 SWOT 更能拉出 Collaborator 與 Context 兩個容易盲點。
